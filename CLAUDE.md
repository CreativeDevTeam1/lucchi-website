# Lucchi Furniture – permanent rules

- LOCAL ONLY. Never run `vercel`, never `git push`, never deploy unless the user says "deploy now" (live site is under client review).
- Look only in: `src`, `public`, `scripts`, `index.html`, `package.json`, `vite.config.js`, `vercel.json`.
- Never open/search: `client-assets`, `Lucchi_Product_Reference_Photos`, `node_modules`, `dist` (except as data source), `grade-report`, big PDFs/ZIPs, `pasted_content*.txt`, `.md` brief files, `.csv` files.
- Never read or print `.env.local`.
- Fonts: Playfair Display for headings, Poppins for everything else.
- Headlines: single style, single colour.
- No custom cursor.
- No product counts shown anywhere (no numbers or counters on the Selected Pieces cards).
- Never invent contact details, prices, names, or claims.
- Animate only `transform` and `opacity`; no jitter on cards; respect `prefers-reduced-motion`.
- Commit locally before any big change (no git repo yet: copy code folders to a backup outside the project).
- Reply in short, simple language.
- Selected Pieces row: it glides on its own like the Collections row (AUTOPLAY=true, 32 px/s desktop, 22 mobile, RESUME_DELAY 1500, FRICTION 0.94), with drag + momentum and the DRAG cursor label. This replaces the old rule "Selected Pieces AUTOPLAY=false" (changed on the client's request). Cards stay visually static (one image, no hover swap or zoom).
- Hero has no buttons (no Explore Collections, no Selected Pieces, no scroll-cue button). Homepage Collections cards are real links to /collections?category=<slug>; a drag never opens them.
- Selected Pieces cards have NO Inquire button. Each whole card is one real link to its piece page (/pieces/<id>); a drag (about 6 px) never opens it. The picture stays static (no zoom, no swap); the cue is a thin line under the name. The DRAG label stays desktop-only (pointer: fine) and acts as the cursor over the cards. This replaces any earlier rule about an Inquire button on the cards.
- Piece pages (/pieces/<slug>, src/components/PiecePage.jsx): show only real, filled-in fields from products.json / images.json (name, category, description, code, dimensions, materials). Never show empty fields, placeholder text ("need client confirmation"), counts or invented text. A price shows only when the piece has an optional `price` (EGP) in Sanity and `showPrice` is on (with an optional `compareAtPrice`, the old price, struck through next to it when it is higher) (changed on the client's request, 2026-10-14); never from local files. One primary button "Inquire about this piece" goes to /contact?type=product&product=<slug>; the contact page pre-selects the product enquiry type and shows the piece.
- Sanity CMS (project szy0z3lw, dataset production): content will live in Sanity once connected. The Studio is a separate folder (../studio-lucchi), not embedded in the site. Never put tokens in site code, `src/`, or any deployed file; the write token lives only as `SANITY_WRITE_TOKEN` in the git-ignored `.env.local`. Import script: `scripts/import-to-sanity.mjs` (dry run by default, `--write` only after the user's OK). Never import prices from local files; prices are typed by the client in Sanity (piece.price, EGP); leave unknown values empty.
- Content now comes from Sanity through a build-time snapshot (Phase 2): `scripts/sync-sanity.mjs` (`npm run sync`, also runs as `prebuild`) writes `src/data/sanity-snapshot.json`; the site reads only that file via `src/data/content.js` (never import products.json / images.json / about.js / contact.js data directly in new code, use content.js). The browser never calls Sanity. Local files are the fallback; Sanity wins when both have a value. Never put tokens in `src/` or the snapshot. The read token is `SANITY_READ_TOKEN` (git-ignored `.env.local`, Vercel env var, build time only). Run `npm run sync` before building. If sync fails it keeps the last snapshot and the build still passes. The only price that is fetched is a piece's optional `price` + `showPrice` from Sanity (EGP); `sync-sanity.mjs` refuses a price anywhere else.

Everything else (email, WhatsApp, hours, social, map) stays hidden until confirmed. Never show "Pending Client Confirmation" text.
- Hero video sources are the original MP4s (never GIFs): the live hero is public/media/hero/hero-hq-{desktop,mobile}.{mp4,webm} + posters (built by scripts/make-hero-from-mp4.mjs from "3 merge.mp4"; mobile is a 4:5 crop because no mobile mp4 exists). Hero limits: 6 MB desktop / 3 MB mobile per file, every frame a keyframe.
